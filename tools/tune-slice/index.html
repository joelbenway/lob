Selecting the solver step size

What this page does

lob integrates the trajectory as an initial-value problem, advancing downrange in fixed spatial steps. Finer steps reduce truncation error but cost linearly more compute. Past a point, that precision is wasted: if input uncertainty already moves the impact by inches, driving solver error to microinches buys nothing.

This page implements the obvious policy: pick the step size whose estimated truncation error sits about an order of magnitude below the uncertainty propagated from your inputs (margin ratio α = 0.1, adjustable). It outputs a single step size in inches for Builder::StepSize, plus the per-input contribution ranking so you can see which measurement dominates the budget.

Demo scope, stated plainly: one fixed trajectory, C1-ICAO (G7 bullet, BC 0.232, 2800 fps), elevation at 1800 ft. Tables baked in below come from pareto.json (sensitivities), step_error_map.json plus the fine step ladder (solver error constant C = 5.46e-08), and floors.json (lob 0.13.0, git 939574c). Full contract: docs/specs/TUNE_TOOL_CONTRACT.md.

Procedure

  1. Enter each input's uncertainty, the ± bound on that quantity, in its stated units. Estimates are acceptable: the margin structure tolerates several-fold errors in these numbers with only √-scale effect on the answer (see assumptions).
  2. Record the source of each bound (instrument spec, datasheet revision, engineering judgment with stated basis). Unsourced numbers are unauditable, so the page treats a missing source the same as a missing value.
  3. Compute. The page propagates the bounds through measured sensitivity coefficients, inverts the fitted error model ε ≈ C·Δx² for the step, and reports the ranking.
  4. If it refuses instead (amber box below), supply the named piece and recompute. Refusal here is fail-closed behavior, not an error: an answer computed from unstated inputs would overstate its own authority.

To see the machinery on example data, Load PRS sketch values fills a plausible shooter (chronograph-class velocity, station-class atmosphere, careful zero), labeled illustrative throughout, never defaults.

Assumptions (stated once, binding everywhere above)

  • Inputs independent (cross-terms neglected; validated as second-order on the measured envelope).
  • Local linearity: sensitivities hold near the operating point; large departures need re-evaluation, not extrapolation.
  • Calibration single-platform (x86_64-linux); step clamped to whole inches in [9, 288].
  • Scope is solver resolution only. Rifle precision, shooter error, and model discrepancy are separate budgets outside this page.
